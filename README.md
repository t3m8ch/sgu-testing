# Автотесты магазина «НВС»

TypeScript, Playwright Test и Allure Report 3. Нужны Node.js 22.18+ и pnpm 12.15.0; Java не нужна.

## Запуск

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm run typecheck
pnpm run test:public
```

Для закрытых сценариев скопируй `.env.example` в `.env` и заполни `NVS_EMAIL` и `NVS_PASSWORD` существующей отдельной тестовой учётки. Для `TM-22` нужны также `NVS_CHECKOUT_NAME`, `NVS_CHECKOUT_PHONE` и пустая корзина. Без этих данных соответствующие проверки будут пропущены. Не отправляй `.env` вместе с проектом.

```sh
pnpm test                       # все сценарии
pnpm run test:auth              # только авторизация
pnpm run test:checkout          # поиск и TM-22
pnpm run report:generate        # можно запускать и после падения тестов
pnpm run report:open
```

Результаты одного прогона хранятся в `allure-results/`. Для защиты используй чистую папку результатов, чтобы не смешать попытки; например, запусти `ALLURE_RESULTS_DIR=defense-results pnpm test`, затем `pnpm exec allure generate defense-results -o defense-report`. Playwright выводит ошибку в терминал; в Allure к упавшему кейсу прикрепляются замаскированный скриншот и лог. Видео и трассировка выключены: они могут хранить личные данные.

Если сайт потребует капчу, `NVS_MANUAL_CAPTCHA=1` открывает браузер и даёт время ввести код или решить видимую капчу. Остальные действия выполняет тест. На публичной форме входа капча при просмотре не появлялась; сценарий зависит от вида проверки, которую покажет НВС. Уровень логирования задаёт `LOG_LEVEL`: `debug`, `info`, `warning`, `error`.

## Какие кейсы покрыты

- `TA-01`: вход по email и паролю. На публичной форме нашли только этот способ. Это проверка успешного входа, а не отдельная проверка флажка «Запомнить меня».
- `TA-02`–`TA-06`: пять наборов данных для одной формы. Для неизвестного email используется адрес в `example.test`. На рабочем НВС все пять наборов отклоняются одним сообщением «Неверный логин или пароль.». В старом PDF для учебного стенда описаны отдельные сообщения для пустых полей и неверного формата.
- `TM-22`: вход гостя через UI, поиск товара `43467`, проверка карточки, добавление двух штук, проверка корзины и заполнение контактов в оформлении. Цена считывается из карточки. **Заказ не отправляется и оплата не выполняется.** Тест пытается удалить добавленный товар и выйти из аккаунта; если уборка не удалась, это видно как ошибка в отчёте.
- `PUBLIC-AUTH`, `PUBLIC-CATALOG`: проверки без учётки, не меняют состояние магазина.

`tests/` содержит сценарии и `expect`, `pages/` — локаторы и действия, `data/` — варианты данных, `fixtures/test.ts` — подготовку Page Objects, лог и уборку. На каждый тест Playwright создаёт новый контекст браузера. Воркеры ограничены одним, так как закрытые тесты могут использовать общую учётку.

## Параллельные прогоны

Используй отдельную учётку для каждого компьютера и не меняй её корзину руками во время прогона. Локальные прогоны под одним пользователем ОС блокируют одновременное использование одного email. Если процесс был аварийно завершён и оставил блокировку, убедись, что других прогонов нет, и удали пустые папки блокировок для этого проекта в `~/.nvs-playwright-locks/`. Если тест не смог подтвердить добавленную позицию или её количество изменилось, он не удаляет её наугад и сообщает, что корзину надо проверить вручную.
